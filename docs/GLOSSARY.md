# 项目术语

## Solution

.NET 工程的组织入口，用来容纳多个职责不同的 Project。它不是应用功能本身，而是让 IDE 和命令行统一构建、测试和管理项目。

## Project

一个可独立编译的代码单元，例如 Core 类库、Desktop 应用或 Tests。分成多个 Project 是为了让依赖边界可由编译器检查。

## MVVM

把界面 View、界面状态 ViewModel 和业务数据或行为分开。它减少 UI 代码与业务规则纠缠，但不意味着所有逻辑都应放进 ViewModel。

## 领域层

表达产品核心规则的代码区域。本项目中，交接时间计算属于领域层，因为即使更换 UI 或数据库，规则仍然成立。

## 基础设施层

负责 SQLite、通知、文件和操作系统能力的具体实现。它回答“如何连接外部能力”，而不是“业务规则是什么”。

## 单元测试

快速验证一个小范围规则的自动化测试。核心时间计算应通过单元测试验证，不需要启动窗口或数据库。

## 集成测试

验证多个组件或真实外部实现能否协作，例如 SQLite 读写和迁移。

## Pull Request

把一个分支的变化提交给维护者审查和合并的 GitHub 协作单元。即使单人项目，也能保留问题、方案、验证和评审记录。

## CI

Continuous Integration，持续集成。每次推送或 Pull Request 时自动执行构建和测试，防止只在开发者电脑上“看起来能用”。

## 语义化版本

常见的 `主版本.次版本.修订号` 版本表达方式。首个稳定 API 前需要结合产品发布策略决定如何采用。

## 活动记录与完成记录

活动记录仍参与当前事件、排程、冲突和提醒。完成记录已退出这些流程，用户端默认
不可见，但仍保存在本地数据库。隐藏、完成和删除是三个不同概念，不能通过清空活动
列表来物理删除完成历史。

## 发布候选

已经具备目标版本的大部分产品能力、正在执行发布前检查的代码状态。发布候选不等于
已经创建安装包、版本 Tag 或 GitHub Release。
